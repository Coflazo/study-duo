# S7 On-device Insights Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Learn, on the user's own computer, which hours of which days and which music go with better focus, show it only when the evidence is strong enough, and suggest what to try next, all checked first on simulated students with known answers.

**Architecture:** A Bayesian linear regression with grouped Gaussian priors, fitted in TypeScript by Cholesky factorisation, with each group's prior precision and the noise precision set by evidence maximisation (MacKay fixed-point updates). Time effects are additive random effects (hour + weekday/weekend deviation + per-day deviation), the random-effects form of a hierarchical prior: a day with few blocks shrinks to its category, a category to the global hour profile. Music effects nest the same way (genre + artist deviation + track deviation) on each block's time shares. A focus index from the S6 signals fills in unrated blocks once it is calibrated. Everything runs when the dashboard opens; nothing leaves the browser.

**Tech Stack:** TypeScript strict, Float64Array linear algebra (no dependency), Vitest, Svelte 5, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-07-study-duo-design.md` (ML: on-device insights; Implicit focus signals). Issue #9.

**Grounding (local course corpus, ml-skill retrieval):**
- Deisenroth, Faisal & Ong, *Mathematics for Machine Learning*, §9.3 Bayesian linear regression (pp. 305 to 311): posterior, predictive, marginal likelihood.
- Murphy, *Probabilistic Machine Learning: Advanced Topics*, §3.5 hierarchical priors (pp. 139 to 141): partial pooling.
- Ruppert & Matteson, *Statistics and Data Analysis for Financial Engineering*, §20.8 hierarchical priors (p. 613): shrinkage of group means.
- Sutton & Barto, *Reinforcement Learning*, ch. 2 multi-armed bandits (p. 26 on): exploration.
- Evidence approximation (MacKay): gamma_g = sum over j in g of (1 - alpha_g * Sigma_jj); alpha_g = gamma_g / sum m_j^2; beta = (N_eff - sum gamma) / weighted residual sum of squares.

## Global Constraints

- No network, no dependency, no WASM: Float64Array and loops. A refit under 300 ms on this 2017 MacBook at p = 300.
- Label: rating (1 to 5) mapped to [0, 1]; unrated blocks only through the calibrated focus index, with lower weight.
- Leakage: the hour and music model never uses focus-index inputs as features (the index is built from them). Walk-forward validation predicts each block from blocks that ended before it.
- An insight is shown only when its posterior SD is under the threshold and its group has enough blocks; an effect is claimed only when its 80% interval excludes zero ("unclear" otherwise). Learning states show progress ("9 of about 25 blocks").
- Copy rules as before; Figma first (Dashboard / Insights 16:572 exists); commits as Coflazo; branch feat/s7-insights; PR closes #9.

## Review Focus

1. **Numerical safety:** near-singular precision (tiny alpha, duplicated features) must not produce NaN; Cholesky adds jitter and reports it. Test: duplicated columns, all-zero group, one data point.
2. **Overclaiming:** with pure-noise synthetic students, the share of "claimed" music effects must stay near the nominal 20% or below, and best windows must not be shown. Test: null simulation.
3. **Cold start:** zero, one and few blocks must render learning states, never errors or empty maps. Test: insights on 0, 1 and 10 blocks.
4. **Data shape drift:** sessions without ratings, listens without genre, blocks across midnight, clock changes (DST). Test: feature builder edge cases.
5. **Cost:** dashboard open with a year of data (about 1,500 blocks, p = 300) stays under a second. Test: timing assertion on synthetic year.

### Task 1: Linear algebra (src/ml/linalg.ts)
Cholesky with jitter, forward and back solves, inverse diagonal, log-determinant, Gaussian sample from a precision factor. Tests against hand-checked 3 x 3 cases and random SPD matrices (A x = b residual, inverse diagonal vs explicit inverse).

### Task 2: Grouped Bayesian linear regression with evidence maximisation (src/ml/blr.ts)
fit(design, y, weights, groups, prior means) returns posterior mean, factor, per-group alpha, beta, log evidence; predict(x) mean and variance; sample(rng). Tests: recovers known weights; an irrelevant group's alpha grows (its weights shrink to zero); fixed alpha matches the closed form; weights act as replicated rows.

### Task 3: Features (src/ml/features.ts)
From sessions, listens and activity: hour bins 06 to 22 (clamped), day of week, weekday/weekend category, music time shares by genre, artist, track (top-K by minutes, rest pooled), source shares (music site, own file, focus sound, silence), controls (nth block of the day, planned length, leisure minutes in the hour before). Tests: shares sum to one, midnight and DST blocks, missing genre, vocabulary cap.

### Task 4: Simulated students and validation (src/ml/synthetic.ts, src/ml/validate.ts)
Students with known hour profiles (weekday vs weekend), a lyrics penalty, a null genre, noise, rating quantisation. Walk-forward MAE vs a running mean; 80% interval coverage; null-effect claim rate. Tests assert recovery, coverage and the null rate.

### Task 5: Focus index (src/ml/focus-index.ts)
Robust z-scores (median and MAD over the last 50 blocks, clipped to plus or minus 3) of the S6 signals; calibration against ratings with a BLR whose prior means are positive for study share and longest stretch, negative for off-task switches and blocked attempts, zero for input; leave-one-out correlation gate (at least 15 rated blocks and r >= 0.3) before any unrated block is filled in; weight from predictive variance; the rating prompt shows only when the index is unsure. Tests on synthetic signals.

### Task 6: Insights (src/ml/insights.ts)
Heat cells (mean, SD, blocks, enough), best window per day and per category, weekday vs weekend summary, music effects vs silence with 80% intervals, Thompson-sampled "try next" (genre, focus sound or silence), block-length suggestion (bandit over 25, 35, 45, 50), model health (walk-forward MAE vs average), learning progress. Tests on synthetic data, including cold start.

### Task 7: Insights screen (Figma first)
Add Suggestions and Model health to Figma 16:572, then the Svelte screen and nav item; light, dark, 380 px.

### Task 8: End-to-end and docs
