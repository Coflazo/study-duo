# S4 Site Lock and Site Categories Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close distracting sites during study blocks, with three site categories (Blocked, Study, Not blocked) that the user files from the popup, the right-click menu, a one-time prompt beside the corner clock, or Settings > Sites.

**Architecture:** Site lists live in `chrome.storage.local` and are read only by extension pages and the background. A pure rule builder turns lists, mode and temporary unlocks into declarativeNetRequest session rules (one rule per filed domain, priority = number of labels, so the most specific entry wins). The background applies the rules while a study block is running or paused, clears them otherwise, and sends already-open tabs of closed sites to the blocked page. Web pages can only ask about and file their own site.

**Tech Stack:** WXT 0.21 (MV3), TypeScript strict, Svelte 5 (blocked page, popup row, Settings > Sites), declarativeNetRequest session rules, contextMenus, Vitest + fake-browser, Playwright + Chrome for Testing.

**Spec:** `docs/superpowers/specs/2026-10-07-study-duo-design.md` (Features v0.1: Tab locker, Site categories; Architecture: Blocking; Security). Issue #6. Figma: Screens page, Blocked 14:433, Settings 18:704 (Sites section 18:815).

## Global Constraints

- No network: rules, pages and fonts are local; no remote lookups of domains.
- Permissions added in this stage, and only these: `declarativeNetRequestWithHostAccess`, `contextMenus`, `host_permissions: ['<all_urls>']` (redirects and reading the active tab's address need host access; the content script already causes the same install warning). Never `tabs`, `webNavigation` or `history`.
- Only domains are stored or shown (`khanacademy.org`), never full addresses, except the single address carried in the blocked page's URL fragment so "Open anyway" can return to it; it is never stored.
- Web pages may only ask for and file their own site (`sender.url` host); they can never unlock, change modes or touch other domains. Timer commands from web pages stay limited to `tick`.
- Blocking is active while a study block is running or paused; breaks and stopped timers clear every rule.
- Unlock = 10 second wait plus a typed reason (at least 3 characters), allowed until the current block ends; hard lock removes the option. Research basis: Grüning et al. 2023.
- Copy: plain, short, no em or en dashes, no filler words; humanizer, voice and stop-slop rules.
- Design: approved Figma wins; tokens from `src/ui/tokens.css`, fonts from `src/ui/fonts.css`; light and dark follow the system theme live.
- Commits authored as Coflazo, Conventional Commits, branch `feat/s4-site-lock`, PR closes #6.

## Review Focus

1. **Subdomain conflicts:** `youtube.com` Blocked with `music.youtube.com` Not blocked must leave YouTube Music open; `google.com` Study with `mail.google.com` Blocked must close only Mail. Test: rule builder priorities, and E2E on two hosts.
2. **Restart and sleep:** session rules vanish on browser restart; a block that is still running must close sites again on startup. Test: background applies rules on startup tick.
3. **Escape hatches:** a web page must not unlock itself or file another domain; a page that frames the blocked page must not get a clickable unlock. Test: message gate unit tests; blocked page renders nothing when framed.
4. **Bad input in Settings:** `https://www.KhanAcademy.org/path`, `*.reddit.com`, IP addresses, `localhost`, empty strings and unicode domains are normalised or rejected with a clear message, never stored half-parsed. Test: `normalizeDomain` table.
5. **Allow only Study:** unfiled sites close, Study and Not blocked stay open, extension pages and the blocked page itself are never redirected into a loop. Test: rule builder and E2E.

### Task 2: Rule builder

**Files:** Create `src/core/blocking.ts`, `src/core/blocking.test.ts`.

**Interfaces:**
- Consumes: `Sites`, `SiteCategory`.
- Produces: `buildRules(input: { sites: Sites; mode: 'closeBlocked' | 'allowOnlyStudy'; unlocked: string[]; blockedPage: string }): Rule[]` where `Rule` is the declarativeNetRequest rule shape; `RULE_ID_BASE = 1`.

Rules: every rule has `resourceTypes: ['main_frame']`. Redirects use `regexFilter: '^https?://.*'` with `redirect.regexSubstitution: blockedPage + '#\\0'`. Per filed domain d with label count n: Blocked → redirect `{ requestDomains: [d] }` priority `n + 1`; Study and Not blocked → `allow` `{ requestDomains: [d] }` priority `n + 1`. Mode `allowOnlyStudy` adds one redirect for every http(s) page at priority 1. Unlocked domains get `allow` at priority 1000. Mode `closeBlocked` with no Blocked domains returns `[]`. IDs are 1..N in a stable order (sorted domains).

- [ ] Write failing tests: close-blocked basic; Review Focus 1 pairs (assert the matching rule with the highest priority for `music.youtube.com`, `www.youtube.com`, `mail.google.com`, `docs.google.com` using a small `winner(rules, host)` helper written in the test that mimics DNR precedence: highest priority, then allow before redirect); allow-only (unfiled host → redirect, Study and Not blocked → allow); unlocked beats Blocked; empty lists → no rules; ids unique and stable.
- [ ] Run → FAIL. Implement. Run → PASS. Commit `feat(site-lock): declarativeNetRequest rule builder`.
